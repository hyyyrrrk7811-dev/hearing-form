# レコーディング事前ヒアリング（無料で公開する構成）

回答者に送るURLは **1つだけ** です。回答者が開くと、その人専用の回答ページ（`?r=…`）が自動で作られます。

## しくみ

| 役割 | 使うもの | 費用 |
|---|---|---|
| 画面（`docs/`） | GitHub Pages（GitHubの無料の公開機能） | 無料 |
| 機材リストの自動更新（`tools/`） | GitHub Actions（毎日1回、PDFを取得して解析） | 無料 |
| 回答・途中保存・メール送信（`apps-script/`） | Google Apps Script + Googleスプレッドシート + Gmail | 無料 |

- **回答の保存場所**: あなたのGoogleスプレッドシート（「下書き」「回答」シート）。公開されません。
- **GitHub（公開される場所）に置くもの**: フォームのプログラム、質問の文章、エンジニア紹介、機材リストだけです。回答・メールアドレス・パスワードは入りません。
- **管理ページ**: スプレッドシートがそのまま管理ページです。Googleにログインしたあなただけが開けます。

## 公開までの手順（所要 約30分）

### Part 1　Google（スプレッドシートとメール）

1. `hyyyrrrk7811@gmail.com` でGoogleにログインし、[Googleスプレッドシート](https://sheets.google.com) で**空白のスプレッドシート**を作り、名前を「ヒアリング回答」にします。
2. メニューの **拡張機能 → Apps Script** を開きます。
3. 最初から入っているコード（`function myFunction() {…}`）を**すべて消して**、このリポジトリの [`apps-script/Code.gs`](apps-script/Code.gs) の中身を**すべて貼り付け**ます。保存（フロッピーのアイコン）を押します。
4. 左の **歯車（プロジェクトの設定）** を開き、下の **スクリプト プロパティ** で、次の2つを追加します。

   | プロパティ | 値 |
   |---|---|
   | `STAFF_RECIPIENTS` | 回答メールの宛先（回答者のメールアドレスには、自動で届きます）。**最初は自分のアドレス1件だけ**でかまいません（例：`hyyyrrrk7811@gmail.com`）。あとで増やすときは、カンマで区切って足します（例：`hyyyrrrk7811@gmail.com, aaa@example.com`） |
   | `PUBLIC_BASE_URL` | 公開するフォームのアドレス（Part 2 で決まる。例：`https://ユーザー名.github.io/hearing-form`。末尾の `/` は付けない） |

5. エディタに戻り、上の関数の選択欄で **`setup`** を選んで **▶ 実行** します。
   「承認が必要です」と出たら、**権限を確認 → アカウントを選択**します。
   「このアプリは Google で確認されていません」と出ますが、自分で作ったスクリプトなので、**詳細 → （プロジェクト名）に移動（安全ではないページ）→ 許可** と進めてください。
   （スプレッドシートの編集とメール送信の許可を求められます）
6. 右上の **デプロイ → 新しいデプロイ** を押し、種類の歯車から **ウェブアプリ** を選びます。
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
   
   **デプロイ** を押して、表示される **ウェブアプリのURL**（`https://script.google.com/macros/s/…/exec`）をコピーしておきます。

### Part 2　GitHub（画面の公開）

1. [GitHub](https://github.com) で無料アカウントを作ります（ユーザー名は、そのままURLの一部になります）。
2. 右上の **＋ → New repository** で、名前を `hearing-form`、**Public**（公開）にして作成します（READMEなどのチェックは入れない）。
3. 作成後の画面にある **uploading an existing file** のリンクを押し、**このフォルダ（`hearing-form`）の中身をすべて**ドラッグして入れ、**Commit changes** を押します。
   - `.github` フォルダは、Finder では見えません。Finder で `Command + Shift + .`（ピリオド）を押すと表示されます。**これも一緒に入れてください**（公開と機材リストの自動更新に必要です）。
4. リポジトリの **Settings → Pages** を開き、**Build and deployment → Source** を **GitHub Actions** にします。
5. リポジトリの **Actions** タブを開き、**公開と機材リストの更新** を選んで **Run workflow** を押します。数分で緑のチェックが付けば公開完了です。
   公開されたアドレス（`https://ユーザー名.github.io/hearing-form/`）が、**回答者に送るURL**です。

### Part 3　つなぐ

1. `docs/config.js` には、Apps Script の **ウェブアプリのURL** がすでに入っています（確認用の接続テストも済み）。Apps Script を作り直してURLが変わったときだけ、GitHubでこのファイルを鉛筆アイコンで編集して貼り直し、**Commit changes** で保存します。
2. Part 1 の `PUBLIC_BASE_URL`（スクリプト プロパティ）に、公開されたアドレス（`https://ユーザー名.github.io/hearing-form`、末尾の `/` なし）を入れます。
3. 公開されたアドレスを開き、ダミーの回答で最後まで送信して、メールとスプレッドシートを確かめます。確認が済んだら、スプレッドシートの「下書き」「回答」シートに入ったテストの行は、削除してかまいません。

## 運用

- **回答の確認**: スプレッドシートの「回答」シート（日時・バンド名・メールアドレス・送信回数・回答全文）、「下書き」シート（回答中のもの）。
- **機材PDFが更新されたら**: 毎日自動で反映されます。すぐ反映したいときは、Actions → **Run workflow**。
- **機材リストの更新に失敗したら**: サイトは前回のリストで動き続け、画面に注意書きが出ます。GitHubからも失敗のメールが届きます。
- **回答メールの宛先を増やす・減らす**: Apps Script の **プロジェクトの設定 → スクリプト プロパティ** で `STAFF_RECIPIENTS` を書き換えるだけです。デプロイし直す必要はなく、次の送信から反映されます。
- **`Code.gs` を直したら**: Apps Script で **デプロイ → デプロイを管理 → 鉛筆 → バージョン：新バージョン → デプロイ**。
- **メールの上限**: 個人のGmailは、1日に**100宛先まで**です（1回の回答送信で4宛先）。超えると、メールだけが止まります（回答はスプレッドシートに保存されます）。
- **回答者に送るもの**: サイトのURL（1つ）だけです。

## 困ったとき

- 画面の保存が「通信できないため、この端末にのみ保存しています」と出る → `docs/config.js` の `apiUrl` と、Apps Script のデプロイ設定（全員がアクセス可）を確認してください。
- `Code.gs` を変えたのに反映されない → 「新バージョン」でデプロイし直す必要があります。
- 機材リストが出ない → Actions タブで、直近の実行にエラーがないか確認してください。

## パソコンの中で動かして確認する（開発者向け）

```bash
python dev/serve.py 8741
# 本物のApps Scriptにつなぐ場合（実際にメールが送られます）
python dev/serve.py 8741 https://script.google.com/macros/s/＜ID＞/exec
```

機材リストを手元で更新する場合: `pip install -r tools/requirements.txt` のあと `python tools/update_equipment.py`。
